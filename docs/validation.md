## Scope and known limits

This section records release v2 limitations. Later development checkpoints
below update individual contracts and interpreter coverage; they do not
establish a new fully verified release.

This is a partial application migration. Dimension, camera and grid decisions,
view navigation, transform helpers, slice planning/request execution, layer-list
extent/unit/name calculations and slice scheduling decisions use handwritten
C++. Most layer model implementation/storage, editing, collection mutations,
Qt controllers, rendering orchestration, IO, settings and plugin management
still contain Python code. See `migration.json` for the boundary.

The independent core has no interpreter dependency. Binding control flow uses
Python models and protocols, NumPy/SciPy primitives for dtype-specific math,
Pint objects, Dask context adapters, executor services and event/plugin callbacks.
The external dependencies and these adapters have not been replaced with native
libraries. Passing the selected tests is not evidence of a full native rewrite.

Native dimension and grid indices use signed 64-bit integers. Extreme ranges,
step counts or grid shapes beyond that representation raise an error; Python's
arbitrary-size integer behavior is not fully preserved. Ranges and coordinates
use double precision. This is a compatibility limit for unusual inputs, not
an assertion of complete model parity.

JSON model serialization and native-state pickle are checked. Python facade
pickling is not promised: the baseline EventedModel contains non-picklable
weak-reference machinery. The GUI checks use hidden windows; they do not
validate the full set of interactive mouse/keyboard/dock-widget workflows.
No Linux/macOS or additional interpreter builds have been validated locally.
